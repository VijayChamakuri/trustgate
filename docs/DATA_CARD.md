# Data card

## A. Stockport MBC purchase-card transactions (real)

| | |
|---|---|
| Publisher | Stockport Metropolitan Borough Council (UK local authority) |
| Where | data.gov.uk dataset `purchase-card-transactions` (CKAN API `package_show?id=purchase-card-transactions`) |
| Licence | Open Government Licence v3.0. Attribution: *Contains public sector information licensed under the Open Government Licence v3.0.* |
| Coverage | Monthly files from January 2017 to the latest published month |
| Integrity | `data/stockport/manifest.json`: URL, SHA-256, bytes and parsed rows per file; the dbt test reconciles every file |
| Redistribution | Raw files are **not** committed; `trustgate real` downloads them, and checksums let anyone verify they have the same bytes |

**Fields as published (by layout).**

| Layout (`schema_version`) | Period | Columns | Notes |
|---|---|---|---|
| `v1_net_10col` | 2017 – 2022 | organisation, department, service category, supplier, purpose of expenditure, procurement (merchant) category, purchase date, settlement date, transaction number, net amount | Labelled years |
| `v2_net_8col` | 2020 (some months) | as v1 without service category and transaction number | Labelled |
| `v3_gross_6col` | mid-2022 onward | organisation, supplier, merchant category (card-network style), purchase date, settlement date, gross amount | Banner row before the header, no department, service or purpose |

**Known publisher issues, and what the pipeline does about them.**

| Issue | Handling |
|---|---|
| One month (May 2024) is an `.xlsx` file with a `.csv` extension | Detected by magic bytes and read with openpyxl |
| One month listed twice (April 2020, identical bytes) | De-duplicated by SHA-256 and counted in `source_files.included` |
| Mixed date formats (`dd.mm.yyyy`, `dd/mm/yyyy`) | `try_strptime` with both formats; `not_null` test on purchase date |
| Settlement dates earlier than purchase dates in some 2024 files | Flagged `is_settled_before_purchase`; dbt **warns** rather than fails (count in `results/real/warehouse.json`) |
| `£` encoded inconsistently (UTF-8, cp1252, latin-1) | Decoder fallback chain |
| 61 raw purpose strings with typos and case variants | Reviewed seed maps them to 21 canonical accounts; unmapped strings fail a dbt test |
| Placeholder purposes ("details to follow", "TO BE ADDED", "MISCLASSIFIED? CHECK BEFORE PUBLICATION") | Kept in the warehouse, excluded from scoring, counted |

**Known limitations.**
- The procurement category in labelled years was assigned by council staff and nearly determines the label. It is excluded from the headline "card feed" setting.
- Merchant strings are truncated by card networks and sometimes carry order references. They are normalised by the `normalize_merchant` dbt macro (drop tokens containing digits, keep the first three tokens).
- A public-sector chart of accounts and coding culture is not a commercial company's.

## B. Synthetic company (policy-agent benchmark)

Generated by [`src/trustgate/generate.py`](../src/trustgate/generate.py). It's deterministic for a given seed. Default world (seed 7): 420 employees, 8 departments, 12 months, about 15k card transactions.

**Planted rates. Every one is an assumption, and the sensitivity analysis varies the important ones.**

| Assumption | Default | Varied in sensitivity analysis |
|---|---|---|
| Review-worthy items waved through by historical reviewers (leniency) | 6% | 0%, 3%, 6%, 10%, 15% |
| Clean items wrongly flagged by historical reviewers | 0.2% | – |
| GL booking errors in reviewer history | 2% | – |
| Memo phrasing drawn from unseen vocabulary in the last 4 months (drift) | 35% | 0%, 15%, 35%, 50% |
| Audited transactions per month (shadow and live) | 500 | 100, 250, 500, 1000 |
| Auto-approve error budget | 1% | 0.5%, 1%, 2% |
| Card-network descriptors with a misleading or generic MCC | 5% | – |
| Processor duplicate charges | 0.5% of eligible | – |
| Employees who split a purchase to dodge a limit (per year) | 12% | – |
| Meals over the per-person cap | emerges from the per-person spend distribution | – |

**Ground truth the agent never sees:** true merchant, true GL account, meal type and attendee count, alcohol on the receipt, cabin class, nightly rate, personal purchase, split group, duplicate-of. Gold labels are written to `data/gold/` (parquet), never into the warehouse the agents read.

**Policy.** [`policy/expense_policy.md`](../policy/expense_policy.md) has stable section IDs that agents must cite.
